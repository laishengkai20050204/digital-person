# 对话长期记忆保留边界

正式对话仍会完整写入 MySQL 近期原始对话表；本规则只决定一轮对话是否交给 Mem0 提取长期记忆，不会删除聊天记录，也不会影响人物正常回复。

## 执行顺序

```text
人物生成回复
  ↓
原始 USER / PERSON 消息写入 MySQL
  ↓
DialogueMemoryRetentionPolicy 检查当前用户消息
  ├─ 可进入长期记忆：交给 Mem0 infer=true
  └─ 明确不应长期保存：跳过 Mem0，返回 0 个 mutation
```

被过滤时，对外结果仍为：

```text
memoryStatus = PROCESSED
memoryMutationCount = 0
```

这表示记忆链路已经正常完成判断，不代表 Mem0 故障。

## Java 侧硬过滤

当前只拦截高置信度内容：

- 完全由测试、占位、ping 或常见调试序列组成的消息；
- 用户明确要求不要记住或不要保存的当前消息；
- 验证码、一次性代码、临时密码；
- 明确赋值的密码、API Key、访问令牌、密钥；
- 常见密钥格式，例如 `sk-...`、GitHub token、Slack token 和 JWT。

规则刻意保持保守。以下内容不会仅因包含相似词语而被拦截：

- “我下周参加软件测试工程师面试”；
- “医生让我下周做过敏原检测”；
- “我正在学习大模型 token 的计费方式”；
- “我平时使用密码管理器保存账号”。

## Mem0 提取安全边界

Java 预过滤之后，Mem0 的提取提示仍强制要求：

- 不保存认证信息、测试消息和占位内容；
- 不保存用户明确拒绝长期记录的当前内容；
- 不把寒暄、确认回复、瞬时情绪、临时状态或调试内容当作长期事实；
- 不把人物回复中的推测、安慰话术或模型补充内容当作用户事实。

`MEM0_EXTRACTION_INSTRUCTIONS` 现在只能添加项目自己的额外提取要求，不能替换上述强制安全边界。

## 职责边界

```text
MySQL 原始对话
保存真实连续聊天，允许滚动摘要继续承接上下文。

Mem0 长期记忆
只保存跨时间仍有价值、未来需要检索的稳定事实。
```

因此测试消息或验证码仍可能短暂存在于受保护的原始聊天数据库中，但不会被复制进长期向量记忆。生产日志和共享终端不应输出这些正文。
